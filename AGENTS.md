# AGENTS.md

PlatformIO Arduino firmware for a DIY AR star-glasses device (观星AR眼镜): a fully standalone, self-contained unit — MCU + BNO085 IMU + GPS module + I2C OLED + prism optics + physical buttons. All astronomy math (Astronomy Engine C port) and the star catalog run on-device; there is NO phone/BLE involvement in the core architecture anymore. Target hardware is an ESP32-C3 SuperMini. `plan.md` (Chinese) is the roadmap and architecture source of truth — read it first.

## Commands

- Build: `pio run`
- Upload: `pio run -t upload`
- Serial monitor: `pio device monitor` (115200 baud, set in `platformio.ini`)
- Do NOT run `pio test`: `test/` contains no Unity tests. Verification = a clean `pio run`.

## Hardware / build config

- Single env `esp32-c3-supermini` (`board = esp32-c3-devkitm-1`); platform is pinned (`espressif32@6.13.0`), framework `arduino`.
- ESP32-C3 SuperMini: 4MB flash, no PSRAM, single I2C controller, native USB. `platformio.ini` MUST keep:
  - `build_flags = -DARDUINO_USB_MODE=1 -DARDUINO_USB_CDC_ON_BOOT=1` (Serial over USB-Serial-JTAG; otherwise `Serial` is UART0 on GPIO20/21 and there is no output)
  - `board_upload.flash_size = 4MB` + `board_build.partitions = default.csv`

## Gotchas

- `test/oled.cpp` is a reference snippet copied from another project; its includes (`pin_config.h`, `oled.h`, `pet_state.h`) don't exist here. Its header comment says to ignore it — do not try to fix, build, or delete it.
- Hard-earned I2C lesson (recorded in `test/oled.cpp` comments): if U8g2's constructor receives SCL/SDA pins, calling `Wire.begin()` separately triggers a duplicate bus init that hard-locks the ESP32 I2C bus → blank OLED, no serial output. Init the bus exactly once. The C3 has only ONE I2C controller, so the OLED (0x3C) and BNO085 (0x4A) share the same `Wire` (GPIO8/9); the bus is initialized once by `oledInit()` and `imuInit()` must NOT re-begin it.
- `lib_deps` has U8g2 (`olikraus/U8g2@^2.36.0`) for the OLED and Adafruit BNO08x (`adafruit/Adafruit BNO08x@^1.2.0`, auto-pulls Adafruit BusIO + Unified Sensor) for the BNO085 IMU. The ESP32 BLE Arduino library ships inside the espressif32 platform but is intentionally unused now (see the disabled-BLE gotcha below).
- `src/ble/BleService.cpp.bak` / `include/BleService.h.bak` is the old BLE UART passthrough, kept as reference for future debug-logging/OTA work. The `.bak` extension keeps it out of the build — do not delete it and do not try to compile it.
- Code is organized per the architecture in `plan.md` (headers in `include/`, sources under `src/drivers`, `src/data`, `src/behaviors`; free functions, no classes):
  - `src/main.cpp` is only the glue layer: `setup()` initializes drivers; `loop()` polls buttons + calls `oledTick()`.
  - `src/drivers/DisplayDriver.*` — U8g2 SSD1306 on hardware I2C (Wire, GPIO8/9). `oledShowScreen()` replaces the whole screen with up to 4 lines; graphics primitives (`oledDrawStr/Line/Circle/Disc/Triangle` + `oledStartFrame/EndFrame`) serve the FOV/guide rendering; actual drawing happens in `oledTick()` called from `loop()` (never draw from ISR/other tasks). The old BLE `oledShowText()` scrolling path has been removed.
  - `src/drivers/ButtonDriver.*` — implemented: non-blocking edge-triggered debounce (`buttonRead()` returns the last pressed `ButtonId`, `buttonClear()` resets it; 200ms debounce, no auto-repeat); action routing handled by `InputManager` (phase 5).
  - Phase 1 (astronomy engine + catalog) is implemented: `AstronomyEngine.*` (thin wrapper over the vendored C sources; star batch path = one EQJ→HOR rotation matrix per frame, sidesteps the engine's 8-star limit), `StarCatalog.*` + `src/data/StarCatalogData.cpp` (60 brightest stars, generated by `python tools/gen_star_catalog.py` — do NOT hand-edit the generated file), `VisibilityRanker.*`, `TimeTravelManager.*`, `GpsManager.*` + `GpsDriver.*` (UART NMEA on GPIO4/3, NVS restore; once a fix is obtained, GPS reading stops and the UTC clock advances from the MCU `millis()` anchor — re-fix only via the 定位 page), and a serial verification console in `main.cpp` (`P`/`T`/`TT`/`O`/`I`/`R` commands; `R` prints the visible ranking once, no continuous auto-print). Numerical cross-check without hardware: `tools/host_verify/` (compile host_verify.c against astronomy.c and diff against official `astronomy-engine` Python package output).
  - Phase 2 (orientation) is now wired in: `ImuDriver.*` — BNO085 on the shared **Wire** (SDA=GPIO8, SCL=GPIO9, same bus as the OLED; INT=GPIO6 as data-ready gate; RST=GPIO5 pulsed by the driver before probing; I2C address 0x4A default / 0x4B with ADDR high), `SH2_ROTATION_VECTOR` @50Hz (absolute, magnetometer-fused, magnetic-north referenced), quaternion → yaw/pitch/roll, and unexpected-reset self-heal (`wasReset` → re-enable report). `imuInit()`/`imuTick()` are called from `main.cpp`; `OrientationManager` applies the single-point calibration residual (magnetic declination + mount error) as a heading/pitch correction, with serial `O` injection still overriding when present.
  - Behaviors implemented: `OrientationManager` (serial injection override + applies calibration residual), `CalibrationManager` (single-point verification — compare view direction vs computed az/alt, persist residual to NVS `"calib"` on commit only), `InputManager` (phase-5 state machine: main menu 定位/校准/观星/时空旅行; B = level-by-level back; serial-printed pages + prompts), `RenderManager` (unified rendering: serial pages print ASCII star names, OLED shows Chinese `nameCn`; FOV star overlay + guide arrow).
