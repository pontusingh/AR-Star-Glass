# AGENTS.md

PlatformIO Arduino firmware for a DIY AR star-glasses device (观星AR眼镜): a fully standalone, self-contained unit — MCU + BNO085 IMU + GPS module + I2C OLED + prism optics + physical buttons. All astronomy math (Astronomy Engine C port) and the star catalog run on-device; there is NO phone/BLE involvement in the core architecture anymore. Final target hardware is an ESP32-C3 SuperMini; current development/testing uses an ESP32-S3 dev board. `plan.md` (Chinese) is the roadmap and architecture source of truth — read it first.

## Commands

- Build: `pio run`
- Upload: `pio run -t upload`
- Serial monitor: `pio device monitor` (115200 baud, set in `platformio.ini`)
- Do NOT run `pio test`: `test/` contains no Unity tests. Verification = a clean `pio run`.

## Hardware / build config

- Single env `esp32-s3-devkitc-1`; platform is pinned (`espressif32@6.13.0`), framework `arduino`.
- Actual module is ESP32-S3-WROOM-1-N16R8 (16MB flash, 8MB OPI PSRAM). The generic devkitc-1 board definition defaults to N8 / no PSRAM, so `platformio.ini` MUST keep:
  - `board_build.arduino.memory_type = qio_opi`
  - `build_flags = -DBOARD_HAS_PSRAM`
  - `board_upload.flash_size = 16MB` + `board_build.partitions = default_16MB.csv`

## Gotchas

- `test/oled.cpp` is a reference snippet copied from another project; its includes (`pin_config.h`, `oled.h`, `pet_state.h`) don't exist here. Its header comment says to ignore it — do not try to fix, build, or delete it.
- Hard-earned I2C lesson (recorded in `test/oled.cpp` comments): if U8g2's constructor receives SCL/SDA pins, calling `Wire.begin()` separately triggers a duplicate bus init that hard-locks the ESP32-S3 I2C bus → blank OLED, no serial output. Init the bus exactly once.
- `lib_deps` has U8g2 (`olikraus/U8g2@^2.36.0`) for the OLED and Adafruit BNO08x (`adafruit/Adafruit BNO08x@^1.2.0`, auto-pulls Adafruit BusIO + Unified Sensor) for the BNO085 IMU. The ESP32 BLE Arduino library ships inside the espressif32 platform but is intentionally unused now (see the disabled-BLE gotcha below).
- `src/ble/BleService.cpp.bak` / `include/BleService.h.bak` is the old BLE UART passthrough, kept as reference for future debug-logging/OTA work. The `.bak` extension keeps it out of the build — do not delete it and do not try to compile it.
- Code is organized per the architecture in `plan.md` (headers in `include/`, sources under `src/drivers`, `src/data`, `src/behaviors`; free functions, no classes):
  - `src/main.cpp` is only the glue layer: `setup()` initializes drivers; `loop()` polls buttons + calls `oledTick()`.
  - `src/drivers/DisplayDriver.*` — U8g2 SSD1306 scrolling-text terminal; text enters via `oledShowText()`, actual drawing happens in `oledTick()` called from `loop()` (ISR/BLE-style callbacks must never draw directly).
  - `src/drivers/ButtonDriver.*` — implemented: non-blocking debounce (`buttonWasPressed()`, edge-triggered); action routing handled by `InputManager` (phase 5).
  - Phase 1 (astronomy engine + catalog) is implemented: `AstronomyEngine.*` (thin wrapper over the vendored C sources; star batch path = one EQJ→HOR rotation matrix per frame, sidesteps the engine's 8-star limit), `StarCatalog.*` + `src/data/StarCatalogData.cpp` (60 brightest stars, generated by `python tools/gen_star_catalog.py` — do NOT hand-edit the generated file), `VisibilityRanker.*`, `TimeTravelManager.*`, `GpsManager.*` + `GpsDriver.*` (UART NMEA on GPIO17/18, NVS restore), and a serial verification console in `main.cpp` (`P`/`T`/`TT`/`O`/`I`/`R` commands; `R` prints the visible ranking once, no continuous auto-print). Numerical cross-check without hardware: `tools/host_verify/` (compile host_verify.c against astronomy.c and diff against official `astronomy-engine` Python package output).
  - Phase 2 (orientation) is now wired in: `ImuDriver.*` — BNO085 on **Wire1** (SDA=GPIO1, SCL=GPIO2; a second I2C peripheral kept separate from the OLED's Wire on GPIO8/9; INT=GPIO10 as data-ready gate; RST=GPIO11 pulsed by the driver before probing; I2C address 0x4A default / 0x4B with ADDR high), `SH2_ROTATION_VECTOR` @50Hz (absolute, magnetometer-fused, magnetic-north referenced), quaternion → yaw/pitch/roll, and unexpected-reset self-heal (`wasReset` → re-enable report). `imuInit()`/`imuTick()` are called from `main.cpp`; `OrientationManager` applies the single-point calibration residual (magnetic declination + mount error) as a heading/pitch correction, with serial `O` injection still overriding when present.
  - Behaviors implemented: `OrientationManager` (serial injection override; real IMU deferred), `CalibrationManager` (single-point verification — compare view direction vs computed az/alt, persist residual to NVS `"calib"` on commit only), `InputManager` (phase-5 state machine: main menu 定位/校准/观星/时空旅行; B = level-by-level back; serial-printed pages + prompts). Only `RenderManager` remains a skeleton (phase 3).
